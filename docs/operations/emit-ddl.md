# The `--emit-ddl` artifact

`fraiseql compile <schema> --emit-ddl <dir>` writes a directory of DDL: one file per GraphQL
type, `<type_snake_case>.sql`, each a `CREATE TABLE IF NOT EXISTS tb_<type_snake_case>` with
one column per field, plus `CREATE EXTENSION IF NOT EXISTS vector` and the declared ANN index
for a type with vector fields.

[Confiture](https://github.com/fraiseql/confiture) reads this directory as a desired state:
`confiture migrate diff --to <dir>` compares it with a live schema and writes the migration.
That makes the directory a **contract** between the two tools, and this page is its
definition. Confiture pins it with a checked-in artifact
(`tests/contract/test_desired_state_fixture.py`), so a change to it is a change on both sides.

## What a file looks like

```sql
-- fraiseql emit-ddl format 1
-- Generated by fraiseql-cli 2.17.0
-- Type: User

CREATE TABLE IF NOT EXISTS tb_user (
    id INTEGER NOT NULL,
    email TEXT NOT NULL,
    display_name TEXT
);
```

- **Line 1** is the format version. A reader checks it before anything else.
- **Line 2** is the compiler that wrote the file. It is provenance, not a compatibility
  signal: two compilers writing the same format write files a reader treats alike.
- The rest is plain SQL. Comments carry nothing a reader needs.

## Guarantees

- **Deterministic.** The bytes are a function of the schema and the compiler version. The
  same schema gives the same files, file for file and byte for byte, whatever order its types
  were declared in and however often it is compiled. Column order is field declaration order,
  which is part of the schema.
- **One file per table.** Two types whose names map to the same table (`HTTPServer` and
  `HttpServer` both become `tb_http_server`) are refused, naming both, and nothing is
  written. Before 2.17.0 the second silently overwrote the first.
- **Additive files only.** The compiler writes its files and touches nothing else in the
  directory. A file left by a type that no longer exists stays; emit into an empty directory
  (or clear the files it wrote) when a type is removed or renamed.

## Version policy

The format version (`EMIT_DDL_FORMAT` in `fraiseql-cli`) rises when a reader of the old
format would misread the new one: a file naming scheme, a statement kind a reader must
handle, a change in what a file means. It does **not** rise for output that only differs in
values (a new column type mapping, a new field), which every reader already handles. A rise
is listed under `### Breaking` in the CHANGELOG, and Confiture's fixture moves with it.

## What it does not carry

- **Your tables.** The `tb_<type>` tables are a column-per-field rendering of the GraphQL
  types. They are not the `tv_`/`tb_` relations a FraiseQL project actually reads, whose
  shape (a `data` JSONB column, Trinity keys) you author. Whether the artifact should model
  those is an open question, recorded on #965.
- **Localized-field indexes.** `compile` prints the expression index each (localized field,
  allowed locale) needs, and `fraiseql doctor --against-db` checks them on a live database
  (see [localization](../guides/localization.md#filter-sort-index)). They are not in this
  directory yet: they index your `tv_` relations, which the artifact does not declare, and
  Confiture's diff currently drops an index whose table its desired state does not declare
  ([confiture#679](https://github.com/fraiseql/confiture/issues/679); FraiseQL side: #1541).
  Create them from the printed report until that is settled.
