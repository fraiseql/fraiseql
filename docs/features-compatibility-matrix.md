# Feature Compatibility Matrix

The crate and feature tables below were regenerated by hand on 2026-10-22 from the
`[features]` and `[dependencies]` tables of `crates/*/Cargo.toml`, and from the release
build commands in `.github/workflows/release.yml`, `.github/workflows/docker-build.yml`
and `Dockerfile`.
When a manifest changes, the manifest is right and this page is stale.

PostgreSQL is the only database backend. No crate has a feature that selects another one.

## Capabilities

Generated from `fraiseql_server::capability::REGISTRY` by `make gen-matrix`; a test
fails when this table and the registry disagree. `fraiseql capabilities` prints the
same list for the server a `fraiseql` binary links, with whether that build has each one.
With `--json`, each entry also carries `schema`: the JSON Schema of every compiled-schema
section it lists (`schema.compiled`) and of every server-config key (`schema.runtime`),
derived from the types the server reads them into. A server-config key is `null` when the
build does not compile its capability in, since its type does not exist there.
A running server's `/health` carries it too, under `capabilities`. For each name it reports
`compiled_in`; `started`, for a capability the server is configured to run (`false` when it
did not start, or when this entry point does not start it); `serving: true` when it mounted
routes; and `healthy`, for a capability that can tell whether it is working right now (the
observer runtime).

"Started by" is each capability's `entry_points`: which ways of serving start it once it is
configured. `fraiseql run` assembles and serves its server the way the binary does, so it
starts the same set. A listener (`Server::serve_on_listener`, the in-process harness) binds
no port its caller did not choose, so it serves no Arrow Flight. The MCP stdio sidecar runs
beside the deployment's HTTP server and starts no deployment-wide work of its own: no
observers, pollers or drains, and no `cron:` scheduler, although it serves functions to its
own requests.

## Known Constraints

1. **`fraiseql-server --no-default-features` builds a library only.** The
   `fraiseql-server` binary has `required-features = ["cli"]`. The no-default build is a
   CI feature combo (`server-no-default` in `.dagger/feature-combos.go`).

2. **`fraiseql-server` always includes PostgreSQL.** It depends on `fraiseql-core` with
   `features = ["postgres", "schema-lint"]`.

3. **`fraiseql-wire` is PostgreSQL-only and Unix-only.** It fails to compile on other
   platforms (`compile_error!` in `src/lib.rs`).

4. **Redis features are independent per subsystem.** `redis-apq`, `jwt-replay`,
   `redis-pkce`, `redis-rate-limiting`, `redis-idempotency`, `redis-usage`, and the observer
   `caching`/`redis-lease` features each enable Redis for their own subsystem only.

5. **`arrow` in `fraiseql` (umbrella) implies `server`.** So does every other server
   pass-through feature.

6. **`fraiseql-cli/run-server`** pulls in `fraiseql-server`. Without it, the CLI has no
   `run` command.

7. **Kafka features pull librdkafka.** `cdc-kafka`, `subscription-kafka` and
   `fraiseql-core/kafka` build it from source through `fraiseql-kafka`.
